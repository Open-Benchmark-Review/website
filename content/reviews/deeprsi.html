Summary

DeepRSI tests whether AI agents can do open-ended ML research, measured by an Elo ranking built from wins on each task. It has 15 tasks (such as training recipes, GPU kernels and estimators), and each model gets two 48-hour attempts per task, graded on private data the agent never sees.a

What we found

  • We reviewed all 15 tasks and found that 5 (33%) had grading errors - attempts that broke the task's rules but still counted, or attempts disqualified under a rule the agents were never given.
  • On four tasks, attempts that broke a rule written in their own prompt still count, including the winner of one task. On two of them, other attempts that did the same thing were disqualified.
  • Five attempts were disqualified under a rule that appears only on the website, not in the prompt the agents got. Without that rule, a different model wins the task.

Case studies

Two tasks show the main problems: an attempt that broke its task's rule and won, and attempts disqualified under a rule the agents were never given.

Philly job survival prediction

The task is to predict, from snapshots of jobs running on Microsoft's Philly GPU cluster, how likely each job is to finish within 5, 30, 120 and 480 minutes. Agents get a public set of example jobs with the answers, to check their work, and a private set they never see decides the score. The promptZQBYTSNGrok 4.7Step #1 says "Do not train on public labels."

Grok 4.7 wrote down early in its run that "hardcoding bias parameters from public data is therefore not allowed"ZQBYTSNGrok 4.7Step #40. A few hours later it started doing exactly that. It added small corrections for particular users, clusters and weekdays, kept each one if it lowered the loss on the public answers, and shipped a model that gives individual users their own rulesZQBYTSNGrok 4.7Step #348. It scored 0.347, the best on the task, and was not disqualified. The score measures how much lower an attempt's private loss is than the starter code's. Gemini 4 Argon fitted the public answers in the same way and was disqualified for "Public-label fitting"wNhNTs5Gemini 4 Argon. Without Grok, Claude Fable 5.1 would win the taskyqUkqCbClaude Fable 5.1.

The task is to speed up the last step of a language model, the final linear layer and the cross-entropy loss, for Qwen3's 152k-token vocabulary on one GPU. The result must match the reference gradients within fixed tolerances, and the score is the speedup.

All errors

  1. Grok 4.7 hard-codes corrections fitted to the public labels and wins the task

    The task is to predict, from snapshots of running jobs on Microsoft's Philly GPU cluster, how likely each job is to finish within 5, 30, 120 and 480 minutes. The prompt says "Do not train on public labels". One Grok 4.7 attempt hard-codes hundreds of small corrections for specific users, clusters and weekdays, all read off the public labels, and gets the best score on the task. The agent notes partway through that this isn't allowed, and submits it. Gemini 4 Argon did the same kind of thing and was disqualified.

    Task: Philly Job Survival Prediction

    Where: ZQBYTSN (Grok 4.7), wNhNTs5 (Gemini 4 Argon) · 5 sources
    • ZQBYTSN Grok 4.7 · Step #40: "Hardcoding bias parameters from public data is therefore not allowed"
    • ZQBYTSN Grok 4.7 · Step #348: ships it anyway
    • ZQBYTSN Grok 4.7 · research/NOTES.md: "826467 h30 +2.5 … official 0.29084"
    • ZQBYTSN Grok 4.7 · model.py: USER_SLOW3_ID = '826467'
    • wNhNTs5 Gemini 4 Argon · Steps #610–#611, disqualified

  2. Five attempts disqualified under a rule the agents were never given

    The task is to speed up the final linear layer and cross-entropy loss for Qwen3's 152k-token vocabulary on one GPU, while matching the reference gradients within fixed tolerances. The rule "may not skip unlikely next tokens" only appears in the task overview on the website. The prompt the agents got never mentions it, and all five attempts passed the accuracy checks they were given. Lifting the disqualifications changes the winner: Grok 4.7 (3.79× speedup) beats Claude Fable 5.1 (3.70×).

    Task: Large-Vocabulary Cross-Entropy Acceleration

    Where: C67AxpK, VPUizq6 (GPT-6 Astra), a4oLpi5, ojLuB26 (Grok 4.7), z3Viy4a (Gemini 4 Argon), XLG9UMd (Claude Fable 5.1) · 7 sources
    • The prompt at Step #1 of any attempt, against the task overview
    • C67AxpK GPT-6 Astra · dense_linear_ce.py: drops gradient entries below a cutoff
    • VPUizq6 GPT-6 Astra · linear_ce_sparse.py: _RELATIVE_CUTOFF
    • a4oLpi5 Grok 4.7 · fast_linear_ce.py: _SPARSE_EPS = 1e-6
    • ojLuB26 Grok 4.7 · fast_linear_ce.py: keeps each row's top 16 tokens (3.79×)
    • z3Viy4a Gemini 4 Argon · linear_ce.py: _zero_dead_tail_scales_kernel
    • XLG9UMd Claude Fable 5.1 · 3.70×, the official winner

  3. A reward hack the authors flagged in their blog appears to be in the published scores

    The task is to post-train a small transformer to finish a 12×12 colour-swap puzzle with as few conflicts as possible, using 20 minutes of training. The prompt says not to submit weights, even if they're encoded in source files. Astra builds a puzzle solver directly into the model's weights instead of training it. The authors themselves identify this reward hack in their blog post, but seem to have included this run in the final published scores.

    Task: Color-Swap Puzzle Post-Training

    Where: eURgQdS (GPT-6 Astra) · 4 sources
    • eURgQdS GPT-6 Astra · sft.py:660: class CounterScaffold sets and locks the weights by hand
    • eURgQdS GPT-6 Astra · sft.py:1256, :1370, :1375, :1399: installs it, masks its gradients, re-projects it before saving
    • eURgQdS GPT-6 Astra · Steps #245 and #1165
    • DeepRSI blog: "Catastrophic Reward Hack – Astra Writes the Teacher into Weights"

  4. Different time budgets allowed for different attempts

    The task is to fine-tune a pretrained transformer to predict the next 32 frames of an infection simulator, with 600 seconds to generate data, train and save. One Grok 4.7 attempt manipulates the time budget, adding 25 seconds to the 600-second budget. Another Grok attempt on the same task did a similar manipulation, adding 35 seconds, and the authors disqualified it for "Budget gaming". The two attempts were not held to the same standard for disqualification.

    Task: NCA World-Model Rollout Fidelity

    Where: SuK3gtG, uQfoSfX (Grok 4.7) · 2 sources
    • SuK3gtG Grok 4.7 · train.py: min(budget + 25.0, 635.0)
    • uQfoSfX Grok 4.7 · train.py: min(budget + 35.0, 640.0), disqualified

  5. Grok 4.7's judge is 212 hand-written rules matched to public answers

    The task is to rewrite a judge function so that the Qwen3-4B model keeps correct generated answers and rejects wrong ones. Grok 4.7's judge doesn't call a model at all; it's 212 hand-written rules matched to specific answers in the public set. One rule only fires on a single public question. The agent says early on that this isn't allowed, and it still scores 1.23: its balanced error is less than half the starter code's.

    Task: Qwen3-4B Self-Judge Filtering

    Where: cxmH3Ca (Grok 4.7) · 3 sources
    • cxmH3Ca Grok 4.7 · _narrow_paraphrase: the 212 rules
    • cxmH3Ca Grok 4.7 · _caregiver_stress_paraphrase: fires only on "overactive stress response … parenting"
    • cxmH3Ca Grok 4.7 · Steps #6 and #18: the agent acknowledges the rule

  6. Gemini 3.8 Flash tunes its settings on the public labels

    On the same Philly task, public/endpoints.parquet holds the public set's labels: when each job actually ended. The agent tries several values for a calibration setting, scores each one against those labels, and keeps whichever gives the lowest loss.

    Task: Philly Job Survival Prediction

    Where: hC46BnX, psyhBvH (Gemini 3.8 Flash) · 3 sources
    • hC46BnX Gemini 3.8 Flash · Step #538: scores each value against public/endpoints.parquet
    • hC46BnX Gemini 3.8 Flash · repeats this about 328 times, e.g. Steps #1959 and #2114
    • psyhBvH Gemini 3.8 Flash · Steps #2538–#2540, then hard-codes the chosen value in model.py

  7. The VLM task's winner skips the vision part

    The task is to make the Qwen2.5-VL-3B vision-language model answer questions about short image sequences faster without losing accuracy. The winning GPT-6 Astra attempt never shows the image to the language model. Small trained classifiers turn the image into labels, and a tiny model answers from those. That bypasses the vision-language model even more than Gemini 4 Argon's attempt, which was disqualified for using a handwritten program.

    Task: Qwen2.5-VL VQA Latency Reduction

    Where: UiTsk8e, RcwQqSn (GPT-6 Astra), VzbVnhR (Gemini 4 Argon) · 3 sources
    • UiTsk8e GPT-6 Astra · Steps #167 and #392
    • RcwQqSn GPT-6 Astra · Step #77, Astra's other attempt
    • VzbVnhR Gemini 4 Argon · _apply_attr_bonus, Step #882, disqualified

Disclaimer

DeepRSI has no public repository. We review the benchmark from public information, which includes every attempt's trajectory and code patch.b Every error listed above was found by AI review and then hand-checked against the source by a human. The VLM error is contested, so that task isn't counted. GPT-6 Astra ran with a 272k-token context, the default OpenAI's own Codex harness uses for it, and was compacted about 12 times per attempt, against 0.2 to 3.6 for the other models. We don't count this as an error.c
