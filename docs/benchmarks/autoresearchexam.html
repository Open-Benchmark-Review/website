Summary

AutoResearchExam tests whether AI agents can do open-ended ML research. Each of 29 tasks, from model merging to causal inference to CPU inference speed, gives an agent 24 hours on one machine to improve a solution, submitting as often as it likes. Each submission gets a validation score; the leaderboard uses a hidden test score, averaged over the 24 hours. All twelve models use the same harness, Terminus 2.a

What we found

  • We reviewed all 29 tasks and all 353 published runs. 4 tasks (14%) have confirmed scoring defects that change scores, below the 20% at which a benchmark is rated Flawed.
  • One is a reward hack that wins its task: Grok 4.7 crashed a submission on purpose to read the grader's state, then rebuilt the hidden answer from a seed the grader left readable.
  • The top four models are within 0.015 of each other and can't be told apart statistically. Each model ran once per task, and 38 runs were re-run under a policy that isn't published.
  • Every published run can be read, which made this review possible. No agent reached the hidden test data during its run.

Case studies

One task where a reward hack decides the winner, and what the leaderboard can and can't tell apart.

Sketched Newton covariance estimator

The task asks an agent to estimate the covariance of a stochastic Newton method from the run alone. The problem's design, noise and seed are hidden; the instruction says the configuration does not reveal the seedinstruction.md:44. But when the grader runs a submission, it writes the seed and the full sample arrays into the folder the code runs ingrader_core.py:130-136.

Grok 4.7 went looking for them. It made one submission fail on purpose, so the grader's error report would show what the code could see:

The next experiment raises a short FAILINFO RuntimeError before any return so the grader first-failure field can expose generator keys and stack frames.

The report came back with the seed. Grok then shipped code that tries nearby seeds, rebuilds the hidden problem and returns the exact covariance. The grader scored it at error 0.000000:

The leaderboard

The leaderboard ranks models by hidden-test AUARC: the time-weighted average, over 24 hours, of the test score of each model's best-on-validation submission. Each model runs once per task.

The top four are separated by 0.015. Resampling the 29 tasks, Opus 5.5 comes first 47% of the time, GPT-6 Astra 24%, and Claude Fable 5.1 and Gemini 4 Argon 14% each. Among the top five, no adjacent gap is statistically clear; the first clear gap is between Claude Opus 5 and Grok 4.7. 38 runs were also re-run under an unpublished policy.

All issues

  1. Grok 4.7 rebuilds the hidden answer from a seed the grader leaves readable, and wins the task

    The task is to estimate the covariance of a stochastic Newton method from its run, without access to the hidden problem. At grading time the grader writes the sample seed and the full sample arrays into the folder the candidate's code runs in, although the instruction says the seed is not revealed. Grok 4.7 made a submission crash on purpose so the grader's error report would show its internal state, then shipped code that recovers the seed and returns the exact answer: error 0.000000. It wins the task with 0.691, against 0.616 for the best honest run (GPT-6 Astra), who would win without it. Opus 5.5 and Gemini 4 Argon saw the same shortcut and declined it.

  2. Shrinking a model's outputs weakens the robustness attack, although the instructions say it can't

    The task is to train a CIFAR-10 classifier that resists adversarial attack. The instruction says the grader rescales outputs so that logit scaling cannot weaken the attack, but the rescaling only corrects large outputs. Claude Opus 5 found that multiplying its last layer by 0.01 adds 2.2 points with predictions unchanged, and declined to ship it. Its shipped model scores 69.1% under the graded attack but 39.7% under a standard stronger attack, below a plain baseline (50.8%), and it ranks 4th. The true ranking under a stronger attack isn't known.

    Task: Budgeted PGD-50 robust CIFAR-10

    Where: opus_5 (Claude Opus 5), instruction, grader · 4 sources
    • opus_5 Claude Opus 5 · #1025: 69.1% under the graded attack, 39.7% under a margin attack
    • opus_5 Claude Opus 5 · #1183: "+2.2 pt" from scaling logits, not shipped
    • instruction.md:34: "prevents logit scaling from weakening the attack"
    • grader_core.py:186-187: divides only by values above 1

  3. Seven of twelve models reach a perfect test score, so the ranking measures time to first submission

    The task is to write a training procedure that makes control policies succeed reliably across 72 hidden environment seeds. Seven of the twelve models reach 72 of 72. GPT-6 Astra did it with its first submission, at 0.24 hours, and GPT-5.6 Sol at 0.68 hours, so the task's score among the top seven only ranks how early each first submitted.

    Task: Reliable on-policy control trainer

    Where: results, instruction · 2 sources
    • Per-submission test scores in the published results: 72/72 for GPT-6 Astra, Gemini 4 Argon, GPT-5.6 Sol, Opus 5.5, Grok 4.7, Claude Opus 5, Claude Fable 5.1
    • instruction.md:10: "Higher is always better"

  4. The instructions promise credit for any interval metric below 1.0; the grader gives zero above 0.0593

    The task is to produce the shortest prediction intervals that still cover the truth in six hidden settings. The instruction says every metric below 1.0 earns more credit, but the grader pays zero for anything at or above 0.0593, so missing coverage in one setting zeroes the run. Scored as the instruction describes, six runs gain 0.05 to 0.20, and GPT-5.6 Sol moves from 7th to 5th of the nine runs we could re-score. The winner is unchanged.

    Task: Shortest valid CI under L2 ECE

    Where: opus_5_5 (Opus 5.5), gpt-5_6_sol (GPT-5.6 Sol), instruction, grader · 4 sources

    • gpt-5_6_sol GPT-5.6 Sol · #885, #892: a tiny validation gain costs the whole test score
    • instruction.md:74-75: "Every metric below 1.0 earns more credit"
    • grader_core.py:18 and grader_core.py:35-37: reward 0 at or above 0.0593
