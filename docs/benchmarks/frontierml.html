FrontierML

Benchmark creator: Induction Labs

Original benchmark: frontierml.org

Version reviewed: Repo 31837e0; 21 tasks × 3 budgets; leaderboard of Oct. 27, 2026

Verdict: *Flawed

Full report, task log and scripts

Summary

FrontierML tests whether AI agents can do ML engineering, measured by a 0-100 score on each of 21 tasks (from training and quantization to vision, audio, proofs and games), where 0 is a baseline result and 100 a strong one. Each model gets three trials per task with $10, $50 and $200 of compute, and a Claude Opus 5.5 reviewer zeroes trials that break the task's rules.a

What we found

  • We reviewed all 21 tasks and found that 7 (33%) had grading errors.
  • In a screenshot diffing task, a reward hack that submits a fixed paragraph written without looking at the screenshot beats 51 of the 57 trials.
  • The hidden test data for all 21 tasks is in a public Hugging Face dataset, and the agents had internet access.b

Case studies

Two tasks show the main problems: a zero point set below what a fixed paragraph reaches, and a reviewer that judged the same move two ways.

Screenshot diffing

The task is to build a model that describes in text what changed between two consecutive screenshots, "without claiming anything the screenshots don't show." A GPT-6 Luna judge checks which of a human's reference observations the description covers, and the score runs from an empty description (0) to the reference observations themselves (100). The judge is toldtasks/screen-difference/environment/validation/validate.py:47 to "not audit or penalize extra candidate claims", so a wrong guess costs nothing.

Before the runs, the organisers scored a fixed paragraphtasks/screen-difference/tests/task/pipeline/baselines.py:27-34 that never looks at the images. It lists common interface changes, such as "A menu, dropdown, context menu, tooltip, popup, dialog, sidebar or panel appeared or disappeared," and scores 32.0. They recorded this in the task filetasks/screen-difference/tests/task/task.yaml:44-47 and left the zero point where it was. The paragraph beats 51 of the 57 trials on the leaderboard. At $10 it beats all 19, and the best of them, by Claude Fable 5.139iyxmClaude Fable 5.1, scores 31.1.

LLM post-training

The task is to post-train Qwen3-4B-Base into a strong chat model. The score averages four public tests, one of them GPQA, a set of hard multiple-choice science questions, and the graded GPQA questions are among the files the agent gets. The rulestasks/llm-post-train/tests/task/review.py:25-31 forbid choosing checkpoints or prompts by their score on those files, and an AI reviewer zeroes trials that do.

Claude Fable 5.1's $50 trial2ikiw0Claude Fable 5.1Steps #119, #135, #136 capped how long its model could think and tested it on 64 GPQA questions. "Budget forcing improved accuracy significantly—GPQA rose from 20% to 42%," it noted, then wrote the cap into its serving script. The reviewer called those runsGrade page of the $50 trial, check on public benchmark data "evaluation, not training or calibration on the items," and the trial kept its 46.2. A Muse Wonder trial2wj08uMuse WonderSteps #203, #213, #214 raised its score on 24 GPQA questions from 4 to 8 with a new chat template and shipped it, and was zeroed. So was Fable's own $200 trial67hhapClaude Fable 5.1Steps #165, #183–#188, which compared checkpoints and thinking budgets on the same file.

The rule calls the supplied files "evaluation-only" and doesn't say where evaluating a change ends and choosing it by its score begins, so the reviewer's reading of Fable's runs is understandable. It drew the line elsewhere for the other two.

All errors

In single tasks

The seven counted tasks, one error each, are screenshot diffing, vision for a ternary LM, Pokémon Random Battle, AR to diffusion conversion, LLM post-training, ternary quantization and AI-text detection.

  1. A fixed paragraph that ignores the images beats 51 of 57 trials

    The task is to describe in text what changed between two consecutive screenshots. A GPT-6 Luna judge checks which of a human's reference observations the description covers, and the score runs from an empty description (0) to the reference observations themselves (100). Before the runs, the organisers scored a fixed paragraph of common UI changes, written without seeing any screenshots, at 32.0, and decided to leave the zero point where it was. That paragraph beats 51 of the 57 trials on the leaderboard, including all 19 at $10, where the best trial, by Claude Fable 5.1, scores 31.1. It does well because the judge only checks what the description covers and never marks a claim as wrong, although the prompt asks for no claims the screenshots don't show.

  2. Most vision trials score 0 because the baseline gets more thinking time

    The task is to add vision to Maple, a language model whose weights are ternary (each one is −1, 0 or +1). The score is accuracy on college-level multiple-choice questions about images, and 0 points is set at what Maple gets on the same questions from the text alone. For that baseline, Maple may think for up to 8,192 tokens and is then forced to answer with one letter. The graded requests allow only 256 tokens per answer, so a submission that keeps to that limit has far less room to think. GPT-6 Astra's $50 trial keeps to it, answers 41.3% of the questions correctly against the baseline's 43.8%, and scores 0, as do 54 of the 57 trials on the leaderboard. The baseline was also raised from 34.9% to 43.8% on Oct. 7, after Claude Opus 5.5, Claude Fable 5.1 and GPT-6 Astra had run, and all 57 trials are scored against the new one.

    Task: Vision for a ternary LM

    Where: 2xzouq (GPT-6 Astra), task page, leaderboard trials · 5 sources
    • Task page on frontierml.org: "Add vision to a ternary language model"
    • tasks/maple-vlm/tests/task/task.yaml:42-55: the floor recipe, measured on 2026-10-07; the previous anchor, thinking off
    • tasks/maple-vlm/environment/validation/validate.py:34: graded requests send max_tokens: 256, temperature 0
    • Leaderboard trial table: 54 of 57 scores are 0

  3. A Pokémon bot scores 0 unless it beats an equally matched opponent

    The task is to build a bot for Pokémon Gen 9 Random Battles. The bot plays 3,000 games against Foul Play, an open-source Pokémon bot, and 0 points is set at a 50% win rate. Foul Play gets about as much computing time per move as the agent's bot, so a faithful copy of it wins about half its games and scores 0, and the organisers chose the 50% mark without measuring this. Claude Opus 5.5's $10 trial rebuilt Foul Play, won 1,491 games and lost 1,509, and scored 0, as do 41 of the 57 trials on the leaderboard. Luck in the battles moves a score by about 1.7 points (one standard error). Among the six models we checked, the winner at each budget leads second place by less than twice that.

  4. The diffusion-only rule is applied unevenly and decides the $200 winner

    The task is to convert an autoregressive language model, which writes one token at a time from left to right, into a text diffusion model, which drafts a block of tokens and refines it over several passes. The prompt asks for a model that "actually generates by iteratively denoising tokens" but doesn't say how much refinement is enough. The reviewer zeroed three trials whose engines accept each block through a final left-to-right check, calling that left-to-right decoding renamed as diffusion. It passed Gemini 4 Argon's $200 trial at 78.8, which refines each block in both directions and then ends with the same check. Applied strictly, the rule would hand the $200 win to Claude Opus 5.5 at 69.5 instead.

    Separately, the server must produce over 450 tokens a second, and the speed check asks for shorter answers than the scored requests do, so a server can tell the two apart. One Claude Fable 5.1 trial sent short requests to a separate fast decoder and passed review at 76.7, which we think the reviewer probably should have caught.

  5. The post-training reviewer passed a trial like two it zeroed

    The task is to post-train the Qwen3-4B-Base model into a strong chat model. The score averages four public tests, one of them GPQA, a set of hard multiple-choice science questions, and the graded GPQA questions are among the files given to the agent. This task's rules forbid choosing settings or checkpoints by their score on such test sets, and the reviewer zeroed a Claude Fable 5.1 trial and a Muse Wonder trial for it. It passed another Fable trial, at $50, which tried a way of limiting how long the model thinks, saw its GPQA accuracy rise from 20% to 42%, and shipped it, scoring 46.2. Two more trials did something similar, a Gemini 4 Argon trial that passed and a DeepSeek V4.1 Flash trial that was never reviewed.

  6. The quantization reviewer passed four trials tuned on test questions

    The task is to quantize Qwen3.5-4B to ternary weights, each stored as −1, 0 or +1, with as little accuracy loss as possible. The prompt bans training, fine-tuning, calibrating "or selecting" on any public benchmark's test questions, yet the graded GPQA questions are among the files given to the agent. The reviewer's checklist leaves out "select", so it passed three Claude Fable 5.1 trials and one Gemini 4 Argon trial that chose serving settings or checkpoints by their GPQA accuracy, which the post-training reviewer zeroes. Fable's $50 trial, for example, compared two thinking modes on GPQA to decide which to serve, and scored 29.3. None of the four wins its budget.

  7. AI-text detection mostly rewards finding the test set's public source

    The task is to detect whether a passage was written by a person or generated by an AI model, in eight languages. The hidden test passages are the test rows of DetectRL-X, a public AI-text detection dataset, and its training rows are allowed and come from the same source. The 9 trials we read that found DetectRL-X and trained on it average 92.0; Claude Opus 5.5's $10 trial found it early on and scored 98.3. The other 9 average 65.3. The two groups are different models: the first is every Claude Opus 5.5, GPT-6 Astra and DeepSeek V4.1 Flash trial, the second every Claude Fable 5.1, Gemini 4 Argon and Muse Wonder trial, so part of the 27-point gap may come from the models.

Across all tasks

Neither is in the 7-task count. The task log records the public test data as a separate error that affects every task, and it is a second reason for the Flawed verdict. The 38 unreviewed trials are listed as a consistency problem, because they were not held to the same rules check as the rest of the leaderboard.

  1. The hidden test data for all 21 tasks is publicly downloadable

    Each task gives the agent a few public examples and keeps a hidden set, the held-out set, for grading. Every task's grader downloads its held-out set from the <task>/private/ folder of one Hugging Face dataset, and that dataset is public, needs no access request, and holds 7,660 held-out files across all 21 tasks. It was created on Sept. 24, before any trial we read; whether it was public while the trials ran can't be told from the public record. Agents can browse the web, and by default the sandbox gets the operator's own Hugging Face login token. Only 10 of the 21 reviewer checklists forbid using the dataset, and the "searching up answers" check the methodology post describes is in none of them. One of the 378 trials we read found the dataset, and it downloaded nothing.

    Affects: all 21 tasks

  2. The rule-breaking review was switched off for 38 trials

    After grading, each trial normally goes to a Claude Opus 5.5 reviewer that reads its log and code and sets its score to 0 if it broke the task's rules. An operator setting, FML_REVIEW_SKIP, turns that review off for a whole batch of runs, and it was on for 21 of DeepSeek V4.1 Flash's 63 trials and 17 of MiniMax M3.1 Flash's 63. Their scores count on the leaderboard next to reviewed ones. A skipped review doesn't make a score wrong, and we read DeepSeek's 21 ourselves: 19 show no rule-breaking, and two probably break the rule against choosing settings on graded test questions, an LLM post-training trial at 20.9 and a ternary quantization trial at 6.4. We did not read MiniMax's 17. The problem is consistency, since these 38 trials were never held to the check that zeroes rule-breaking trials elsewhere on the leaderboard.

Disclaimer

FrontierML publishes its grading code, reviewer checklists, the 0 and 100 points of every score, the hidden test data (see above) and every trial's trajectory (the agent's full log) and grade page;c submitted weights and server code, and the pre-review scores of zeroed trials, are not public. We used an AI model to review all 21 tasks and 378 trials for 6 models, and hand-checked every finding.
