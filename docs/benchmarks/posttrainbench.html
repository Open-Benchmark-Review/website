PostTrainBench

Benchmark creator: Ben Rank, Hardik Bhatnagar, Ameya Prabhu, Shira Eisenberg, Karina Nguyen, Matthias Bethge, Maksym Andriushchenko (aisa-group)

Original benchmark: posttrainbench.com

Version reviewed: v1.2, repository commit 62c69d36; 6 target benchmarks × 4 base models; leaderboard of Nov. 4, 2026

Verdict: Verified

Summary

PostTrainBench tests whether AI agents can post-train a language model. Each agent gets 10 hours on one H100 GPU to make a small base model (Qwen3-1.7B, Qwen3-4B, SmolLM3-3B or Gemma-3-4B) score as high as possible on one target benchmark, such as AIME 2025, GPQA or HumanEval. That makes 24 tasks, and each agent runs each one two or three times. LLM judges read every run for cheating.a

What we found

  • We reviewed all 24 tasks and found that none had grading errors that affect the score.
  • We found no reward hacks. In each of the 24 tasks we read the highest-scoring run that the benchmark's cheating checks did not flag, and every one is legitimate: no test data in training, no swapped-in model, no tampering with the evaluation.
  • Seven of the 19 entries, including the top five, have no public runs, so their results can't be checked.

Case studies

GPQA Main

The task is to post-train a base model so it answers GPQA Main, 448 graduate-level multiple-choice questions in biology, chemistry and physics. The answer must end with a line like "ANSWER: B", and the four choices are shuffled for each of three scoring seeds.

Base models score between 2% and 14%, mostly because they don't answer in that format. So the first thing any agent gains is the format, and the format alone is worth a lot: a model that answers "B" to every question scores 26.0%gpqa_letters.py in the audit folder. The official instruct models, built by the model developers with far more compute, score 36.2%. The best agent, GPT-6 Astra, reaches 33.5%, and Kimi K3, Opus 4.8 and Gemini 3.1 Pro end up below the constant answer.

GPQA carries 24% of the leaderboard scoreVersion 1.2 release notes, more than any target except AIME. Nothing here is a scoring error: the scorer is correct and learning the format is a real part of post-training. But on this target, even the best agents finish only a few points above a model that always answers "B".

All issues

  1. Clean HumanEval runs are scored as if they did nothing, with no reason given

    The task is to post-train a base model to write Python functions that pass HumanEval's unit tests. Version 1.2 gives four HumanEval cells the base model's score, although their runs were judged clean. Opus 5's two Qwen3-4B runs scored 81.7% and 83.5% in version 1.1, and Epoch AI also found them clean; in version 1.2 the cell is 36.6%, the base score. The scoring code gives the base score for a cheating flag, a missing run or a model that fails to evaluate, and the leaderboard doesn't say which. Our code review rules out the new HumanEval sandbox. The most likely cause is an unpublished version 1.2 judge verdict. Unconfirmed, so not counted.

    Task: HumanEval: Opus 5 / Qwen3-4B, Fable 5 / SmolLM3, Grok 4.5 / SmolLM3, GLM 5.3 Flash / SmolLM3

    Where: 17415833, 17419570 (Opus 5), 17415251 (Fable 5), collect.py, leaderboard · 5 sources

    • 17419570 Opus 5 · scored 83.5% in version 1.1, all checks clean
    • 17415251 Fable 5 · scored 65.9% in version 1.1, all checks clean; cell now 6.1%
    • scripts/collect.py:187-210: one base score for three different reasons
    • Leaderboard data: fallbackType: false in all 504 cells

  2. On GPQA, always answering "B" earns most of every agent's credit

    The task is to post-train a base model to answer graduate-level science multiple-choice questions. Base models score 2–14% because they rarely give an answer in the required format. A model that always answers "ANSWER: B" scores 26.0% across the three scoring seeds, which is worth 4.2 leaderboard points. That is 70–100% of every agent's GPQA credit, and GPQA carries 24% of the score. The scorer is correct, and learning the answer format is part of post-training, so this is not counted. But the most heavily weighted target barely separates the agents on the science.

    Task: GPQA Main, all four base models

    Where: GPQA scorer, reproduction · 2 sources
    • src/eval/tasks/gpqamain/evaluate_final_eval.py: letter extraction and per-seed shuffling
    • Our re-implementation: scripts/reviewers/scorers/gpqa_letters.py in the audit folder

  3. The check that the right model was submitted passes the forbidden instruct models

    Agents must post-train the base model they are given, not submit the official instruct version. The programmatic check compares only architecture fields in the model's config, not its weights. Our re-implementation passes the unmodified official instruct config of all four base models. The instruct versions of two of them sit in the task's own model cache. The LLM judge still reads every trace, and we found no swap it missed.

    Task: every run

    Where: identity check, cache list · 2 sources
    • src/judges/judge_tools/model_identity_check.py:25-35: architecture fields only
    • containers/download_hf_cache/resources.json: Qwen3-4B and gemma-3-4b-it cached

  4. The shared contamination checker skips the most common training-data format

    Agents and judges get the same tool for checking training data against the test set. It reads plain text fields, so chat-format records (messages or conversations), the usual format for fine-tuning data, produce nothing to check and come back clean. It also misses paraphrased, translated and answer-only overlap. The judge's instructions say a clean check does not clear a run, so the effect is small.

    Task: every run

    Where: checker, reproduction · 2 sources
    • src/judges/judge_tools/contamination_check.py:642-672: reads input documents
    • Our re-implementation: scripts/reviewers/setup/decon_input_reimpl.py

  5. The math scorers misread a few answer formats

    The task is to post-train a base model to solve AIME and GSM8K problems; the scorer takes the last number in the answer. A number after the answer line, "(70)", "70%" or "x=70" is scored wrong, and "70.0001" or "7*10" can be scored right. The agent's own copy of the scorer is more lenient than the final one, and the prompt doesn't say so. Each case is worth well under one point.

    Task: AIME 2025 and GSM8K

    Where: scorer, tests · 2 sources
    • src/eval/exact_numeric_match.py:30-86: last-number extraction
    • Our tests: scripts/reviewers/scorers/test_numeric.py

Disclaimer

This is a full review of the code and a targeted review of runs: we read the top unflagged run in every task, not every run. We used AI reviewers to find every issue, which we then hand-checked. We reviewed version 1.2; Epoch AI reviewed version 1.1 and rated it Verified.b
